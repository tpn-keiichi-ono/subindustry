# 運用手順

導入・日々の運用・設定の変更・トラブル対応の手順です。仕組みは [DESIGN.md](DESIGN.md) を参照してください。

関数を「実行する」とは、Apps Script エディタで関数を選んで「実行」を押すことです。
メニュー「履歴機能」には利用者向けの「権限を承認する（初回のみ）」だけを置いているので、管理者の作業や選んだ行のモーダルを開く処理は、エディタから関数を実行します。
確認や結果の画面はスプレッドシートの側に出るので、スプレッドシートを別のタブで開いたまま実行してください。
**トリガーを設置する関数は、必ず管理者アカウント（トリガーの所有者）1人だけが実行してください。**
別の人が実行すると、同じトリガーが二重にでき、記録が二重になります。

## 最初の導入（管理者アカウントで）

1. リポジトリ直下の `.gs`・`.html` を Apps Script に反映します（「[clasp で同期する](#clasp-で同期する)」または「[エディタに貼り付ける](#エディタに貼り付ける)」）。
2. 追跡シート（`新FMT`・`新FMT2`）の2行目（見出し行）を確かめます。
   - `最終更新日時`・`得意先` の見出しが、それぞれちょうど1つある
   - ボタン列 `クレデンシャル`（セル内で改行）`オファリング登録` と `変更履歴` が、それぞれちょうど1つあり、**追跡範囲（`D3:AF`）の外**にある
   - 追跡範囲に結合セルが無い
3. `test.gs` の `DIFF_RULES` が、追跡したいシート・範囲になっているか確かめます。
4. `setupDiffTracking()` を実行し、権限を承認します。今の値が比較基準になり、差分追跡のトリガー3つが設置されます。
5. 次の関数を実行します。
   - `setupCredentialLauncher()`（ボタン列を設定・補充）
   - `setupChangeHistoryLauncher()`（変更履歴ボタン列を設定・補充）
   - `setupHistorySidebarAutoOpen()`（開いたときにサイドバーを自動表示。使う場合）
6. 必要なら `protectTimestampColumns()` を実行し、最終更新日時の列を管理者だけが編集できるようにします。
7. サイドバーに「承認する」ボタンを出す場合は、「[承認用のウェブアプリを用意する](#承認用のウェブアプリを用意する)」を行います。

### 利用者の権限の承認（初めて使う人）

初めて使う人は、スクリプトをまだ承認していないため、サイドバーは出ても履歴を読み込めません（サイドバーに「権限の承認が必要です」と出ます。ボタンから開くモーダルも読み込めません）。
サイドバーは管理者の権限で動く起動時トリガーで開きますが、サイドバーやモーダルから呼ぶ関数は開いた本人の権限で動くためです。

承認のしかたは2つあります。どちらも1回だけで、2回目からは要りません。

- サイドバーの「承認する」ボタン（承認用のウェブアプリを用意した場合）：新しいタブで Google の承認画面が開くので、承認してもらいます。
  「権限の承認が完了しました」と出たらタブを閉じます。数秒でサイドバーに履歴が表示されます。
- メニュー「履歴機能」→「権限を承認する（初回のみ）」：表示される画面で承認すると、サイドバーが開き直して履歴が表示されます。

開いただけで承認の画面を出すことはできません（承認の画面は、本人がボタンやメニューから開いたときにしか出ないため）。

### 承認用のウェブアプリを用意する

サイドバーの中からは承認の画面を出せないため、「承認する」ボタンは同じプロジェクトのウェブアプリ（`HistorySidebar.gs` の `doGet`）を新しいタブで開きます。
ウェブアプリを「アクセスしているユーザー」として動かすと、まだ承認していない人には Google の承認画面が出ます。ページは承認の状態を表示するだけで、シートは読み書きしません。
管理者が1回だけ次を行います。URL を設定するまでは、サイドバーはボタンを出さずにメニューでの承認を案内します。

1. Apps Script エディタの右上の「デプロイ」→「新しいデプロイ」を押します。
2. 「種類の選択」の歯車から「ウェブアプリ」を選び、次のようにして「デプロイ」を押します。
   - 説明：`履歴機能の承認`（何でもよい）
   - 次のユーザーとして実行：**ウェブアプリにアクセスしているユーザー**
   - アクセスできるユーザー：**（組織名）内の全員**（スプレッドシートを使う人が全員組織内の場合。組織外の人もいるときは「Google アカウントを持つ全員」）
3. 表示された「ウェブアプリの URL」（`https://script.google.com/…/exec`）をコピーします。
4. `HistorySidebar.gs` の `HS_OPTIONS.authorizeUrl` に貼り付けて保存します（`…/exec` で終わる URL だけを使います。テスト用の `…/dev` は使えません）。

ウェブアプリはデプロイしたときの版のコードで動きます。**新しいサービスを使い始めるなど、権限が変わる変更をしたら**、
「デプロイ」→「デプロイを管理」→ 鉛筆のアイコン →「バージョン」を「新バージョン」にして「デプロイ」を押してください（URL は変わりません）。
古い版のままだと、ボタンから承認しても新しい権限が足りず、サイドバーが読み込めないままになります。

## 日々の運用

| こんなとき | すること |
|---|---|
| 追跡シートに行を足した | `setupCredentialLauncher()`・`setupChangeHistoryLauncher()` を実行し、最終行までボタンを補充する |
| 行を追加・削除した | 何もしなくてよい（自動で記録し、追跡を続ける。削除と追加を続けて行っても、行のずれに気づいて突き合わせ直す） |
| 列を追加・削除した | 追跡が止まる（トーストで知らせる）。`DIFF_RULES` の範囲を確かめ、`setupDiffTracking()` を実行する |
| 行を並べ替えた・ドラッグで動かした | そのシートの次の編集のときに、行のずれに気づいて突き合わせ直す（移動しただけの行は記録しない）。`得意先`・`案件名` がどちらも同じ行が複数あると見分けられないため、並べ替えはなるべく避ける。おかしいときは `setupDiffTracking()` で比較基準を取り直す |
| 差分を確認した | `変更履歴_差分` の「確認済み」にチェックを入れる |
| サイドバーの自動表示をやめたい（自分だけ） | 本人が `toggleHistorySidebarAutoOpen()` を実行する（実行するたびにオン・オフが切り替わる） |
| サイドバーの自動表示を全員やめたい | `removeHistorySidebarAutoOpen()` を実行する |

`setupDiffTracking()` を実行し直しても、これまでの記録（`変更履歴_差分`・`変更時点スナップショット`）は消えません。比較基準だけが取り直されます。

### アカウントプランシートの作成

メニュー「アカウントプランシート作成」→「作成開始」で、処理するシート名を入力します。
E列が入力済みで M列が空の行ごとに、テンプレートをコピーして M列に URL を入れます。
5分たつと途中で止まるので、残りがあればもう一度実行してください（M列が空の行だけを続けて処理します）。
「他の処理が実行中のため…停止しました」と出たときも、少し待ってからもう一度実行すれば続きから処理します。

テンプレートのファイルと保存先のフォルダは、`コード.gs` の `executeCopyProcess()` の「設定項目」で変えます。

履歴サイドバーの得意先名の横の「アカウントプラン」ボタンは、`33シナリオ攻略先リスト` の E列（得意先）と M列（URL）を読んで、同じ得意先の URL を開きます。
URL を入れたあとは、サイドバーの「再読み込み」（または1分ほど待つ）で反映されます。シート名・列を変えたときは、`HistorySidebar.gs` の `HS_OPTIONS.accountPlan` を直してください。

### オポチュニティキャンバス

追跡シートで行を選び、履歴サイドバーの「キャンバス」で開きます（エディタから `openOpportunityCanvas()` を実行しても、選んでいる行で開きます）。
「印刷・PDF」で A4 横1枚に印刷でき、印刷画面の送信先を「PDF に保存」にすると PDF になります。
右上の「−」「＋」でキャンバスを縮小・拡大でき、倍率（例「100%」）を押すと元の大きさに戻ります。「全体を表示」を押すと、キャンバス全体がスクロールせずに見える大きさになります（もう一度押すと 100%）。倍率は次に開いたときも引き継がれます。

#### サンプルデータで確かめる

`samples/新FMT_サンプルデータ.tsv` は、新FMT の見出し（サブインダストリー〜提案を勝ち取るための戦略・差異化要素）の並びどおりに作った架空の5行です（タブ区切り、見出し行なし）。

1. ファイルをテキストエディタで開き、すべて選んでコピーする
2. 新FMT の空いている行の「サブインダストリー」の列（C列）のセルを選んで貼り付ける
   （または「ファイル」→「インポート」→ アップロード → 区切り文字「タブ」→「選択したセルでデータを置換する」）
3. 必要なら、`setupCredentialLauncher()`・`setupChangeHistoryLauncher()` を実行して、新しい行にもボタンを入れる
4. 貼り付けた行を選び、履歴サイドバーの「キャンバス」で確かめる

貼り付けは追跡範囲への編集なので、変更履歴_差分 にも記録されます。確認が終わったら、行ごと削除してください（削除も「行削除」として記録されます）。
アカウントプラン（リンク）は空にしてあります（架空の URL は開けないため）。

列の割り当てを変えたいとき（列を増やした・見出しを変えたなど）は、`OpportunityCanvas.gs` の `OC_OPTIONS.sections` の `headers` に見出し名を書きます。
モーダルの下に「見つからない列があります」と出たら、見出し名が一致していません。

### サンプルの履歴（画面の確認・説明用）

追跡シートで行を選んでから `addSampleHistory()` を実行すると、選んだ行の得意先にサンプルの履歴を追加します（複数行を選ぶと得意先ごとに追加。一度に20件まで）。

- クレデンシャル 5件・オファリング 5件（クレデンシャルに紐づけ。実績・予定・期限超過を含む）
- 変更の記録 5件（過去2週間ほどの日時。その行の追跡範囲の、見出しのある列を使う）

追跡シートのセルの値は変わりません。サンプルは名称の先頭が「【サンプル】」、登録元・登録者・編集者が「サンプルデータ」、変更の記録のイベントIDが「SMP-」で始まります。
使い終わったら `removeSampleHistory()` を実行して、この印の付いた行だけを削除してください（本物の履歴は消えません）。
件数や内容は `サンプルデータ.gs` の `SMP_OPTIONS` で変えられます。

### タスク管理

`タスク管理` シートで、新FMT の行（案件）ごとのタスクを管理します。今は1行ずつ手で追加します。

**用意する（管理者が1回）**：`setupTaskSheet()` を実行します。`タスク管理` シートが無ければ作り、1行目に見出し
（サブインダストリー・得意先・案件名・タスク・担当者・期限・状況・メモ）を書いて、全行にプルダウンを付けます。
すでにシートがあって見出しが入っている場合は、見出しは書き換えません（違う見出しのときは止まります）。入力済みのタスクは消えません。

**使い方**：

1. 空いている行の「サブインダストリー」をプルダウンで選ぶ
2. 隣の「得意先」のプルダウンが、そのサブインダストリーの得意先だけになるので選ぶ
3. 隣の「案件名」のプルダウンが、そのサブインダストリー・得意先の案件だけになるので選ぶ
4. タスク・担当者・期限（日付）・状況（未着手・対応中・完了）・メモを入れる

- 選択肢は新FMT のサブインダストリー・得意先・案件名の列から作ります（全角・半角と空白の違いは同じ値とみなします）。
- 左の列を選び直して、右の列の値が合わなくなったときは、右の列が空になります（合う値はそのまま残ります）。
- 左の列が空のときは絞り込みません（得意先から先に選ぶと、その得意先のすべての案件が出ます）。
- 新FMT にサブインダストリー・得意先・案件が増えたときは、その行を編集すると選択肢に入ります。全行をまとめて作り直すときは `setupTaskSheet()` を実行します。
- 行の並べ替え・追加・削除は自由にしてかまいません（タスク管理シートは差分追跡の対象外です）。

プルダウンの切り替えは単純トリガーの `onEdit` で行うため、トリガーの設置や利用者の承認は要りません。
選択肢を作るシート・見出し・列の名前・状況の選択肢は、`TaskManagement.gs` の `TASK_OPTIONS` で変えられます（新FMT2 も使うときは `sourceSheets` に足す）。

### 列の保護

`protectSpecificColumnsWithLock()` を実行すると、名前が `案件_` で始まるシートの P・R・T・X・AA・AB 列が、実行した人だけ編集できるようになります。
新しい「案件_」シートを足したら、もう一度実行してください（既にある保護は作り直しません）。

## 設定を変えるとき

- **追跡範囲（`DIFF_RULES` の `ranges`）**：ボタン列を含めないでください。変えたら `setupDiffTracking()` を実行します。
- **追跡するシートを増やす**：`DIFF_RULES` にシートを足し、そのシートにも上の見出しを用意してから `setupDiffTracking()` と2つのボタン列の設定を実行します。シートが増えてもトリガーは3つのままです（1回の処理で読むのは、関係するシートだけ）。行のずれに気づけるよう、`得意先`・`案件名` の見出しは追跡範囲の中に置いてください。
- **行を見分ける列（`DIFF_ROW_OPTIONS.keyHeaders`）**：行のずれの検知と突き合わせに使う列の見出しです（既定は `得意先`・`案件名`）。見つからない見出しは使わず、1つも無いシートではずれの検知をしません。
- **入力項目（`CRED_OPTIONS.fields`）**：`label` が `クレデンシャル履歴_記録` の見出しになります。見出しを変えるときは、古い見出しを `renamedColumns` に書くと、次に開いたときに書き換えて使い続けます。
- **権限が変わる変更をした**（新しいサービスを使い始めたなど）：エディタで関数を一度実行して再承認し、`reinstallDiffTriggers()` を実行します。承認用のウェブアプリを用意している場合は、デプロイも新しいバージョンにします（「[承認用のウェブアプリを用意する](#承認用のウェブアプリを用意する)」）。

## clasp で同期する

[clasp](https://github.com/google/clasp) を使うと、リポジトリと Apps Script エディタの中身をコマンドで同期できます。

どの方法で同期する場合も、Apps Script のファイルはリポジトリ直下に置いてください。フォルダに入れるとエディタのファイル名にフォルダ名が付き（`src/HistorySidebarView` など）、モーダル・サイドバーが「HTML ファイルは見つかりませんでした」で開けなくなります。

### 準備（最初の1回）

```bash
npm install -g @google/clasp   # または npx @google/clasp …
clasp login
cp .clasp.json.example .clasp.json
```

`.clasp.json` の `scriptId` に、Apps Script エディタの「プロジェクトの設定」→「ID」を入れます（`rootDir` は `.` のまま）。
`.claspignore` で、push するファイルを Apps Script のファイル（`.gs`・`.html`・`appsscript.json`）だけに絞っています。消さないでください（`tests/` の `.js` まで送ると、プロジェクト全体が動かなくなります）。
`npx clasp status` で、push されるファイルの一覧を確かめられます。

### 変更を反映する手順

**`clasp push` はエディタ側の中身をリポジトリの内容で置き換え、リポジトリに無いファイルはエディタから消します。** 必ず次の順で行ってください。

1. `npx clasp pull` でエディタの最新を取り込む
2. `git status`・`git diff` で、エディタ側だけで変わっていた所が無いか確かめる（あればコミットしておく）
3. 変更を入れ、`npm run check` と `npm test` を通す
4. `npx clasp push` で反映する
5. 必要なら、上の「設定を変えるとき」の関数（`setupDiffTracking()` など）を実行する

ファイル名は、エディタ側の名前に合わせています（`test.gs`・`Changehistory.gs` など）。
名前を変えると、`clasp pull` で古い名前のファイルも戻ってきて、同じ関数が2つになります。変えるときはエディタ側でも同じ名前に変えてください。

## エディタに貼り付ける

clasp を使わない場合は、変更したファイルの中身をエディタの同じ名前のファイルに貼り付けて保存します。

- ファイルを新しく作るときは、`.gs` は「スクリプト」、`.html` は「HTML」で、拡張子を除いた同じ名前にします。
- `.gs` と `.html` に同じ名前は付けられません。
- 古い版のファイルを残したまま新しいファイルを足すと、同じ名前の関数・定数が2つになって動かなくなります。

## トリガー

| 関数 | 種類 | 設置する関数 |
|---|---|---|
| `recordDiffEdit` | 編集時 | `setupDiffTracking()` |
| `pauseDiffOnStructureChange` | 変更時 | `setupDiffTracking()` |
| `catchUpDiffTracking` | 時間主導（5分ごと） | `setupDiffTracking()` |
| `onCredentialLauncherEdit` | 編集時（2つのボタン列で共通） | `setupCredentialLauncher()`・`setupChangeHistoryLauncher()` |
| `autoOpenHistorySidebar` | 起動時 | `setupHistorySidebarAutoOpen()` |

`onOpen`（メニュー）と `onEdit`（タスク管理のプルダウン）は単純トリガーなので設置は要りません。どの関数も「1つだけ存在する」ように作るので、何度実行しても増えません。

## トラブル対応

### 確かめるための関数

- `diagnoseDiffTriggers()`：トリガーの一覧と、差分追跡の3つがそろっているか
- `diagnoseDiffState()`：追跡シートごとの状態（停止していないか、シート名・`DIFF_RULES`・最終更新日時の列・行数・列数が保存時と同じか、取りこぼし・行の確かめが残っていないか）

結果は実行ログに出ます。

### よくあるメッセージ

| メッセージ・症状 | 原因と対処 |
|---|---|
| 「差分記録を停止しました。Apps Scriptの実行履歴を確認してください。」 | 記録中にエラーが起きた。実行履歴でエラーを確認し、`diagnoseDiffState()` で状態を見て原因を直してから `setupDiffTracking()` を実行する |
| 「…の列構成が変わったため差分追跡を停止しました」 | 列の追加・削除。`DIFF_RULES` を確かめて `setupDiffTracking()` を実行する |
| `Exactly one timestamp header is required` | 見出し行に `最終更新日時` が無い、または2つ以上ある |
| `Merged cells are not supported` | 追跡範囲に結合セルがある。結合を解除する |
| `Edit exceeds 2000 tracked cells.` | 一度に2,000セルを超える貼り付け。追跡は止まるので、`setupDiffTracking()` を実行する |
| `Log sheet has unexpected headers` | `変更履歴_差分` の1行目が変わっている。バックアップを取り、見出しを元に戻す |
| 「…が DIFF_RULES の ranges に含まれています」 | ボタン列が追跡範囲に入っている。範囲から外して `setupDiffTracking()` を実行し、もう一度ボタン列を設定する |
| 「他の処理が実行中です。少し待ってからもう一度お試しください。」 | ほかの書き込みと重なった。少し待って保存し直す |
| 「この履歴は他の人が先に変更しています」「…得意先が変わっています」 | 開いたあとに、ほかの人の編集や並べ替えがあった。モーダルを閉じて開き直す |
| サイドバーに「権限の承認が必要です」と出る・モーダルが読み込めない | まだ承認していない。サイドバーの「承認する」か、メニュー「履歴機能」→「権限を承認する（初回のみ）」で承認する |
| サイドバーに「承認する」ボタンが出ない（案内の文だけ） | `HS_OPTIONS.authorizeUrl` が空か、`…/exec` で終わる URL になっていない |
| 「承認する」で開いたタブに「一部の権限が承認されていません」 | 承認画面で外したチェックがある。そのページの「もう一度承認する」で、すべてにチェックを入れて承認する |
| 「承認する」で承認したのに、サイドバーが読み込めないまま | ウェブアプリのデプロイが古い版で、権限が足りていない。デプロイを新しいバージョンにする。急ぐときはメニューから承認する |
| 承認したのに「権限の承認が必要です」と出る | ブラウザで複数の Google アカウントにログインしていると、別のアカウントとして動くことがある。シークレットウィンドウか、1つのアカウントだけでログインした状態で開く |
| ボタンを押してもモーダルが開かない | 全員で開かないときは `diagnoseDiffTriggers()` で `onCredentialLauncherEdit` があるか確かめ、無ければボタン列の設定を実行する |
| メニューのどちらかが出ない | `onOpen` が2つあると、どちらか一方しか動かない。`npm run check` で確かめる |
| タスク管理のプルダウンが絞り込まれない・「…の見出しがちょうど1つ必要です」と出る | 新FMT の2行目に `サブインダストリー`・`得意先`・`案件名` の見出しが1つずつあるか、タスク管理シートの1行目の見出しが変わっていないか確かめる |
| タスク管理のプルダウンに無い値を入れられない | 新FMT に無い値は選べないようにしている。先に新FMT に行を足す |
| 「「HistorySidebarView」という HTML ファイルは見つかりませんでした」など | エディタのファイル名にフォルダ名が付いている（`src/HistorySidebarView` など）。リポジトリ直下のファイルで同期し直し、フォルダ名の付いたファイルが残っていれば削除する（残すと同じ関数が2つになる） |
| 変更履歴に「記録を探せませんでした」 | `変更時点スナップショット` に `得意先` の列が無い。追跡シートの見出しが `得意先` になっているか確かめる |

### 古い版から上げるとき

差分ログの列構成が古い版（編集者メールアドレスの列が無い）のときは、`upgradeDiffTrackingV3()` を1回実行します。比較基準はそのままで、列だけを足します。
`DIFF_RULES` も変えた場合は、代わりに `setupDiffTracking()` を実行してください。
