# 設計ドキュメント

このドキュメントは、仕組みの全体像と「なぜそう作ったか」を残すためのものです。
コードを変えるときは、ここに書いた前提を崩していないかを先に確認してください。

## 1. 目的

スプレッドシート「シナリオ攻略先リスト」の追跡シート（`新FMT`・`新FMT2`）は、複数人が日常的に編集します。そこで次の3つを満たすことを目的にしています。

- **誰が・いつ・何を変えたかを後から確かめられる**こと。上書きされた値も、文字単位の差分で残す。
- **得意先ごとのクレデンシャル（実績紹介）とオファリング（提案）の予定・実績を、同じシートの行から登録・確認できる**こと。
- これらを、**スプレッドシートから離れずに、少ない操作で見られる**こと。

監査のための完全な記録ではなく、「通常の運用で起きる変更をできるだけ取りこぼさずに残す」ことを狙っています（限界は「8. 既知の制約」）。

## 2. 構成

| ファイル | 役割 |
|---|---|
| `DiffTracking.gs` | 差分追跡の本体。編集トリガー・変更トリガー・時間トリガー、比較基準（非表示シート）、差分ログ、行スナップショット、行の追加・削除の自動反映 |
| `CredentialHistory.gs` | `onOpen`（メニュー）、ボタン列のチェック検知（両モーダル共通）、クレデンシャル・オファリングの登録・編集・削除、記録シートの管理、モーダルの大きさの記憶 |
| `CredentialDialog.html` | クレデンシャル・オファリング履歴のモーダル |
| `ChangeHistory.gs` | 変更履歴モーダルのデータ作成（スナップショットと差分ログの突き合わせ）、ボタン列の設定 |
| `ChangeHistoryDialog.html` | 変更履歴のモーダル |
| `HistorySidebar.gs` | 履歴サイドバーのデータ（選択行・全得意先の一括データ）、開いたときの自動表示 |
| `HistorySidebarView.html` | 履歴サイドバー |

すべてのファイルは同じグローバルスコープで動きます。依存の向きは次のとおりで、逆向きの依存は作らないようにしています（`typeof X === 'function'` で存在を確かめて呼ぶ1か所を除く）。

```
DiffTracking.gs  ←  CredentialHistory.gs  ←  ChangeHistory.gs  ←  HistorySidebar.gs
（差分追跡）        （共通部品・クレデン）     （変更履歴）          （サイドバー）
```

例外：`DiffTracking.gs` の `recordDiffEdit()` は、ボタン列の操作を記録しないために `credIsLauncherEdit_()` を `typeof` で確かめてから呼びます。

## 3. シートとデータモデル

| シート | 種類 | 内容 |
|---|---|---|
| `新FMT`・`新FMT2` | 追跡シート | 業務データ。2行目が見出し、3行目以降がデータ。`DIFF_RULES` で追跡範囲（例 `A3:AF`）を指定。見出し「最終更新日時」の列に自動で日時が入る |
| `__CHAR_DIFF_<シートID>` | 非表示 | 比較基準。追跡範囲の各セルを「型の1文字＋値」のトークン（`S文字列`、`N数値`、`D日時のミリ秒`、`F数式`、`B真偽値`）で保持する |
| `変更履歴_差分` | 記録（追記のみ） | 1セルの変更につき1行。記録日時・イベントID・編集者・シート・セル・列名・種類・変更前・変更後・差分（リッチテキスト）・確認済み |
| `変更時点スナップショット` | 記録（追記のみ） | 1イベント×1行につき1行。固定列（記録日時・イベントID・編集者・シート・行番号・変更セル）のあとに、追跡シートの見出しごとの列（見出し名で列を合わせる） |
| `クレデンシャル履歴_記録` | 記録 | 1件1行。列は**見出し名で識別**する（並べ替え自由、足りない列は自動で右端に追加） |

### イベントID

`接頭辞-yyyyMMdd-HHmmss-8桁` の形です。接頭辞で発生元が分かります。

| 接頭辞 | 発生元 |
|---|---|
| `EVT` | 通常の編集（編集トリガー） |
| `REC` | 取りこぼし回収（時間トリガー） |
| `ROW` | 行の追加・削除の反映 |
| `DLG` | （旧版）ダイアログからの書き込み |
| `CRD` | クレデンシャル・オファリングの登録・編集・削除（`変更履歴_差分` にのみ記録） |

### クレデンシャル記録の列

`ID, 登録日時, 得意先, 予定日, 実施日, 種別, 役職, 氏名, 名称, フリーコメント, 担当者名, 担当部署, 紐づくクレデンシャルID, 登録者, 登録元（登録時の行）, 更新者, 更新日時, 削除者, 削除日時`

- 入力項目は `CRED_OPTIONS.fields` で定義し、その `label` が見出しになる。項目の追加は設定だけで済む（列は自動追加）。
- **予定／実績は保存しない**。実施日が空なら「予定」、入っていれば「実績」と、表示のたびに決める（食い違いを起こさないため）。
- **削除は論理削除**（削除者・削除日時を入れて非表示）。`deleteMode: 'hard'` で行ごと削除にもできる。
- 紐づけはオファリング側に親（クレデンシャル）の ID を持つ。1つのクレデンシャルに複数のオファリング。
- 旧版からの移行：`renamedColumns`（見出しの付け替え：日付→実施日、備考→フリーコメント）、`legacyColumns`（旧列の値を読み取りに使う：宛先→氏名）。

## 4. 処理の流れ

### 4.1 セルの編集（`recordDiffEdit`、インストール型 onEdit）

1. ボタン列の操作なら何もしない。
2. ドキュメントロックを取る。60秒取れなければ、そのシートに「取りこぼし」の印を付けて終わる（エラーにしない）。
3. 行数だけが比較基準と違えば、先に「行の追加・削除の反映」（4.3）を行って終わる。
4. 状態を確かめる（停止中・設定の変更・列数の変化があれば例外 → そのシートを停止）。
5. 編集範囲を比較基準と比べ、変わったセルだけを記録：最終更新日時 → 差分ログ → 行スナップショット → 最後に比較基準を進める。

**比較基準を最後に進める**のは、途中で失敗しても次回の比較で同じ差分を取り直せるようにするためです。

### 4.2 取りこぼし回収（`catchUpDiffTracking`、5分ごと）

印の付いたシートだけ、追跡範囲全体を比較基準と比べて記録します（編集者は「不明（取りこぼし回収）」）。スクリプトや API による書き込みは編集トリガーが動かないので、ここで拾われます。

### 4.3 行の追加・削除（`pauseDiffOnStructureChange` → `diffResyncRows_`）

行数だけが変わった場合は、追跡を止めずに次の順で処理します。

1. 比較基準（変化前の行）と現在の行を、行全体のトークンを連結したキーで突き合わせる。前後の一致部分を除いた範囲で LCS を取る（範囲が大きすぎる場合はまとめて扱う）。
2. 一致しなかった「すき間」ごとに：旧と新の行数が同じなら「中身が変わった行」としてセル単位で記録、違えば旧側を「行削除」（行全体の内容を見出し付きで）、新側の中身のある行を「行追加」として記録。
3. そのシートだけ比較基準を取り直し、状態の行数を更新する。

どのトリガーが先に届いても同じ結果になるよう、編集トリガー（4.1 の3）と取りこぼし回収（4.2）も同じ処理を呼びます。

**列の追加・削除は自動では反映しません。** `DIFF_RULES` の範囲は列の文字（`A3:AF`）で決めているため、列が増減すると追跡する列の意味がずれる（ボタン列が範囲に入り込むなど）からです。停止して、管理者が範囲を確かめて `setupDiffTracking()` を実行します。

### 4.4 ボタン列からモーダルを開く（`onCredentialLauncherEdit`）

1. チェックが入った単一セルのみ対象。見出し行を1回だけ読んで、どのボタン列か（クレデンシャル／変更履歴）を判定する。
2. **すぐにモーダルを開く**（得意先の確認や履歴の読み込みはモーダル側で行う）。
3. 開いたあとでチェックを外す。

インストール型トリガー自体の起動待ち（約1秒）は Google 側の仕組みで短くできません。それ以外の処理を最小にしています。

### 4.5 モーダル

- 開くとすぐ「読み込み中」を表示し、`google.script.run` でデータを取る（くるくるは CSS ではなく JavaScript で回す。OS の「動きを減らす」設定でも止まらないように）。
- **大きさはブラウザの窓幅の95%**。開いたあと `google.script.host.setWidth` で合わせ、測った大きさを利用者ごとに保存して、次回からその大きさで開く（Google 側が開いたあとの変更を無視する環境があるため）。
- クレデンシャルの登録・編集・削除は**楽観的更新**：画面を先に更新し、保存は裏で1件ずつ順番に送る。失敗した行は「再試行／取り消す」を出す。サーバー側は、開いたときの値と今の値を比べて、他人の変更を上書きしない。
- サイドバーから開くときは、選んだ履歴（`focusId` / `focusEventId`）の位置で開く。

### 4.6 履歴サイドバー

- サイドバーは開いている間、選択行を問い合わせ続ける（操作中 0.25秒、1分動きがなければ1.2秒、10分で4秒、タブが隠れている間は3秒）。同じ行なら得意先も読まない軽い応答にする。
- **履歴は全得意先ぶんをまとめて読み込んでおき**、行の切り替えでは読み込まない。1分ごと・「更新」ボタン・モーダルを開いたあと数分間に読み直す。
- 幅は Google の仕様で約300pxに固定（変えられない）。
- 開いたときの自動表示は、管理者が設置したインストール型の起動時トリガー1つで全員分をまかなう。個人ごとにオフにできる（ドキュメントプロパティにメールアドレス単位で保存）。

## 5. 設計上の判断と理由

| 判断 | 理由 |
|---|---|
| 行ごとの起動はチェックボックス＋インストール型 onEdit | スプレッドシートにはセル内ボタンが無い。単純トリガーはモーダルを開けない。図形ボタンは行を特定できない |
| ボタン列は差分追跡の範囲外に置く | チェックの ON/OFF を履歴に残さないため。`setupCredentialLauncher()` などは範囲内なら止まる |
| 履歴は別シートに得意先単位で持つ | 同じ得意先が複数行・複数シートにあっても1か所にまとまる。行のセルに持つと分散する |
| 得意先の照合は NFKC 正規化＋空白除去 | 全角・半角や空白の揺れで別の得意先にならないように |
| 変更履歴は「シート名＋得意先」で探す | 行番号は削除・並べ替えで変わる。代わりに、得意先名を変える前の記録は出ない |
| 記録シートの列は見出し名で識別 | 項目追加や列の並べ替えで壊れないように。足りない列は自動追加 |
| 予定／実績を保存しない | 実施日から決めれば矛盾が起きない |
| 論理削除＋全操作を `変更履歴_差分` に記録（`CRD-`） | 誤削除からの復旧と、誰が何をしたかの確認のため |
| 文字列は数式として解釈されない書き方 | `=` で始まる入力が数式として実行されるのを防ぐ（差分ログはリッチテキスト、記録は先頭 `'`） |
| ロックはドキュメントロック1種類 | 差分追跡とクレデンシャル記録が同じスプレッドシートに書くため、順番を1本にする |
| 比較基準は値のトークンで保存し、`=` で始めない | 非表示シートで数式が実行されないように |
| 画面は楽観的更新 | `google.script.run` は1往復1〜2秒かかる。待たせないため |
| 起動時は見出し1回だけ読んで即モーダル | トリガー後の処理時間を最小にするため |

## 6. 画面のデザイン

モーダル・サイドバーは、`docs/design-reference/history-modal.template.html`（Claude Design で作ったデザイン）を元にしています。新しい画面もこれに合わせます。

- **フォント**：本文 `Inter` + `Noto Sans JP`、日付・数値は `Azeret Mono`（Google Fonts）。
- **色**：主色（ボタン）`#36A191`、文字 `#1b1b1c` / `#5a6660` / `#8a968a`、区切り線 `#EFF2EF`、線（レール）`#E2E7E2`。
  - クレデンシャル：塗りの丸 `#1F6E5E`、文字 `#1F5E55`（緑）。
  - オファリング：輪 `#8B6FD6`、文字 `#6B4FB8`（紫）。「オファリング追加」も紫系。
  - 削除・期限超過：`#B42318`（背景 `#FCEDEC`）。
- **一覧**：左に日付欄（128px、右寄せ）、●／○ の印と縦線（同じまとまりをつなぐ）、内容、右に操作。クレデンシャルと紐づくオファリングを1つのまとまりとして区切る。
- **追加・編集**：右からせり出すパネル（幅 380px）。種別はカード、区分（予定／実績）はセグメント。
- **文言**：見出しは短い名詞、ボタンは動詞（「追加する」「変更を保存」）。エラーは「何が起きたか＋どうすればよいか」。
- **アクセシビリティ**：キーボードで操作できる（`role`・`aria-expanded`・フォーカスリング）。入れ子のボタンを作らない。

## 7. 設定の要点

| 設定 | 場所 | 内容 |
|---|---|---|
| `DIFF_RULES` | `DiffTracking.gs` | 追跡するシートと範囲。変えたら `setupDiffTracking()` |
| `DIFF_OPTIONS` / `DIFF_ROW_OPTIONS` | `DiffTracking.gs` | シート名・上限・回収間隔など |
| `CRED_OPTIONS` | `CredentialHistory.gs` | ボタン列の見出し（改行・空白は無視して照合）、入力項目、紐づけ、予定／実績、削除方式 |
| `CHG_OPTIONS` | `ChangeHistory.gs` | 変更履歴ボタン列の見出し、表示件数 |
| `HS_OPTIONS` | `HistorySidebar.gs` | サイドバーの表示件数・文字数・自動表示 |
| `DIALOG_WIDTH_RATIO` | 各モーダルの HTML | モーダルの幅（窓幅に対する割合） |

## 8. 既知の制約

- **並べ替え・行のドラッグ移動は検知できない**（行数が変わらないため）。管理者が `setupDiffTracking()` を実行する。
- **列の追加・削除は追跡が止まる**（4.3）。
- 比較は「最後に記録した値」との比較。記録の間に何度も変わった途中の値は残らない。数式の再計算は対象外（数式は式として比べる）。
- トリガーの起動待ち（約1秒）は短くできない。サイドバーの切り替えも 0.5〜1秒ほどかかる。
- サイドバーの幅は約300pxで固定。
- 得意先名を変える前の変更履歴は、変更履歴モーダル・サイドバーに出ない。
- 社外アカウントなど、Google が編集者のメールアドレスを渡さない場合は「取得不可」「不明」になる。

## 9. テスト

- `tests/lib/gas-mock.js`：`SpreadsheetApp`・`PropertiesService`・`LockService` などの最小限のモック。`src/` を1つのスコープで読み込む `loadProject()`。
- `tests/row-resync.test.js`：行削除・挿入・その前後の編集が正しく記録され、二重記録しないこと。
- `tests/change-history.test.js`：変更履歴の突き合わせ（得意先での絞り込み、別行の除外、空欄の扱い、スナップショット比較の補完）。
- `tests/sidebar.test.js`：選択行の取得、全得意先の一括データ（削除済みの除外、得意先名の揺れの吸収）。
- 画面は、HTML の `<script>` の先頭に `google.script.run` のモック（`withSuccessHandler` で渡された関数を呼ぶ Proxy）を差し込み、Playwright で表示・操作を確かめる。
