# 設計

スプレッドシート「シナリオ攻略先リスト」に組み込む Apps Script（コンテナバインド・V8）の設計をまとめます。
運用の手順は [OPERATIONS.md](OPERATIONS.md) を参照してください。

> **シート名について**：シート名は設定で変えられます。このドキュメントでは、差分追跡の対象のシート（今の名前は「スーパー・GMS」「コンビニ」「百貨店」。前の名前は新FMT・新FMT2）を「新FMT」、
> リクエストを選ぶシート（今の名前は「サービスリクエスト」）を「リクエスト」、タスクのシート（今の名前は「サービス案タスク管理」）を「タスク管理」と書きます。
> 今の名前と書いてある場所は、OPERATIONS.md の「シート名の一覧」を見てください。

## 全体像

| 仕組み | ファイル | 何をするか |
|---|---|---|
| 差分追跡 | `test.gs` | 追跡シートのセルの変更を、文字単位の差分・編集者・変更時点の行全体つきで記録する |
| クレデンシャル・オファリング履歴 | `CredentialHistory.gs`・`CredentialDialog.html` | 得意先ごとの履歴を登録・編集・削除する。メニュー（`onOpen`）とボタン列の起動もここ |
| 変更履歴 | `Changehistory.gs`・`ChangeHistoryDialog.html` | 行（得意先）ごとの変更をタイムラインで見せる |
| 履歴サイドバー | `HistorySidebar.gs`・`HistorySidebarView.html`・`AuthorizeView.html` | 選んだ行に合わせて、上の2つの要約を表示する。まだ承認していない人には承認の入口を出す |
| アカウントプランシート作成 | `コード.gs`・`Loading.html` | E列に得意先がある行ごとに、テンプレートのファイルをコピーして URL を M列に入れる |
| 列の保護 | `自動入力部分のシート保護.gs` | 名前が「案件_」で始まるシートの決まった列を編集不可にする |
| オポチュニティキャンバス | `OpportunityCanvas.gs`・`OpportunityCanvasDialog.html` | 追跡シートの1行（1件の案件）の値を、キャンバスの枠に並べてモーダルで見せる |
| サンプルデータ | `サンプルデータ.gs` | 画面の確認用に、選んだ行の得意先へサンプルの履歴を追加する・まとめて削除する |
| サービス管理 | `ServiceManagement.gs` | 新FMT でリクエストのある案件を「リクエスト」シートにプルダウンで選び、リクエストをもとにサービス案を考えて名前でまとめる・棄却する。単純トリガーの `onEdit` もここ |
| タスク管理 | `TaskManagement.gs` | 別のシート「タスク管理」で、サービス案ごとの検討の進捗をタスクで管理する |

ファイル名は Apps Script エディタ側の名前に合わせています（`clasp pull` で同じ名前になるように）。
差分追跡のファイルが `test.gs` という名前なのはそのためです。
ファイルはリポジトリ直下に置きます。フォルダに入れると、同期したときにエディタのファイル名にフォルダ名が付き（`src/HistorySidebarView` など）、
`createTemplateFromFile('HistorySidebarView')` が HTML を見つけられなくなるためです。

### 1つのグローバルスコープ

Apps Script はプロジェクトの全ファイル（リポジトリ直下の `.gs`）を1つのグローバルスコープに読み込みます。

- ファイルをまたいで関数・定数を使えます。たとえば `CredentialHistory.gs` は `DIFF_RULES` や `diffAppend_()` を、
  `Changehistory.gs`・`HistorySidebar.gs` は `cred*` の関数を使います。
- 同じ名前の `const` があると読み込みで失敗し、同じ名前の `function` はどちらか一方しか動きません。
  `onOpen` はプロジェクトに1つだけ（`CredentialHistory.gs`）で、ほかのメニューはそこから呼びます（`apAddMenu_()`）。
- 別のファイルの関数を「無くても動く」ように使うときは `typeof 関数名 === 'function'` で確かめてから呼びます
  （例：`recordDiffEdit` の `credIsLauncherEdit_`）。

## シートと保存場所（データモデル）

### 追跡シート（`新FMT`・`新FMT2`）

`DIFF_RULES` に書いたシートです。2行目が見出しで、追跡範囲は `D3:AF` です。見出し行には次が必要です。

| 見出し | 数 | 用途 |
|---|---|---|
| `最終更新日時` | ちょうど1つ | 差分追跡が変更した行に日時を入れる（「（自動入力）」の付いた見出しも可）。追跡範囲から自動で外す |
| `得意先` | ちょうど1つ | 履歴の照合に使う。全角・半角と空白の違いは無視する（`credNormalize_`） |
| `クレデンシャル`（改行）`オファリング登録` | ちょうど1つ | ボタン列（チェックボックス）。**追跡範囲の外** |
| `変更履歴` | ちょうど1つ | ボタン列（チェックボックス）。**追跡範囲の外** |

ボタン列のチェックは差分として残したくないため、追跡範囲に含まれていると `setupCredentialLauncher()` などが止まります。

### `変更履歴_差分`（追記のみ）

1セル1行です。列は次の11列で、`Changehistory.gs`・`HistorySidebar.gs` は B〜I 列を位置で読みます（列の順番を変えないでください）。

`記録日時`・`イベントID`・`編集者メールアドレス`・`シート`・`セル`・`列名`・`種類`・`変更前`・`変更後`・`差分`・`確認済み`

- 文字列はすべてリッチテキストで書きます（`=` で始まっても数式にならない）。空欄は `（空欄）` と書きます。
- `差分` は、増えた文字を赤の太字、消えた文字を赤の取り消し線で示します。
- `確認済み` はチェックボックスで、人が確認の印に使います。
- 古い版の列構成（8・9・10列）が見つかったときは、`diffLogSheet_()` が足りない列を差し込みます。

### `変更時点スナップショット`（追記のみ）

イベントID × 変更した行ごとに1行です。固定の6列のあとに、追跡シートの見出しごとの列が並びます。

`記録日時`・`イベントID`・`編集者メールアドレス`・`シート`・`行番号`・`変更セル`・（見出しごとの列…）

- 見出しの列は見出し名で探し、無ければ右端に追加します。同じ見出しが2つある列は `見出し [列記号]`、見出しの無い列は `D列（見出しなし）` になります。
- 値は表示値（`getDisplayValues`）です。

### `__CHAR_DIFF_<シートID>`（非表示）

比較基準です。追跡シートと同じ位置に、セルの値を「型の1文字＋値」で入れます。
`S`（文字列）・`N`（数値）・`B`（真偽値）・`D`（日時。ミリ秒）・`F`（数式）。空欄は空のままです。
先頭が `=` にならないので、比較基準の中で数式が動くことはありません。

### `__REQUEST_LISTS`（非表示）

`リクエスト` シートの A〜D のプルダウンの候補を、数式で作るシートです（サービス管理。`svcBuildLists_` が作り直すので、手で編集しない）。
A〜D 列が新FMT の案件（候補にできるものだけ）、E 列がその案件を選んだ行の数（`SUMPRODUCT`）、F1 がレイアウト（JSON）、
G 列から右が `リクエスト` の行ごとの候補（同じ行番号。列ごとに `widths` ぶんの欄を取り、`TRANSPOSE(UNIQUE(FILTER(…)))` で横に並べる）です。

### `クレデンシャル履歴_記録`

1件1行です。列は**見出し名**で見分けるので並べ替えは自由ですが、見出し名は変えないでください。足りない列は右端に追加します。

`ID`・`登録日時`・`得意先`・（入力項目：`予定日`・`実施日`・`種別`・`役職`・`氏名`・`名称`・`フリーコメント`・`担当者名`・`担当部署`）・`紐づくクレデンシャルID`・`登録者`・`登録元（登録時の行）`・`更新者`・`更新日時`・`削除者`・`削除日時`

- 入力項目は `CRED_OPTIONS.fields` で決まり、`label` が見出しになります。
- 文字列は先頭に `'` を付けて書きます（`credText_()`）。数式・日付・数値に変わりません。
- 削除は既定で「削除者・削除日時を入れて非表示」（`deleteMode: 'soft'`）です。
- 以前の版の見出し（`日付`→`実施日`、`備考`→`フリーコメント`）は自動で書き換え、`宛先` 列は読み取りだけに使います。

### プロパティ・キャッシュ

| 場所 | キー | 中身 |
|---|---|---|
| ドキュメント | `CHAR_DIFF_STATE_V1` | 追跡シートごとの状態（比較用シートのID、シート名、`DIFF_RULES` の内容、最終更新日時の列、行数・列数、停止中か） |
| ドキュメント | `CHAR_DIFF_DIRTY_V1_<シートID>` | 取りこぼしの印（回収されると消える） |
| ドキュメント | `CHAR_DIFF_ROWCHECK_V1_<シートID>` | 行の確かめの印（構成の変更でロックが取れなかったとき。回収で行数・ずれだけを確かめると消える） |
| ドキュメント | `CRED_DIALOG_SIZE_V1_<メール>` | その人のブラウザに合わせたモーダルの大きさ |
| ドキュメント | `HS_AUTO_OFF_<メール>` | サイドバーの自動表示をオフにした人 |
| ユーザー | `CRED_COLUMN_WIDTHS_V1` | その人の列幅 |
| ユーザーキャッシュ | `HS_CUSTCOL_<シートID>` | 得意先列の位置（10分） |

### イベントID

`接頭辞-yyyyMMdd-HHmmss-8桁` です。接頭辞で記録のきっかけが分かります。

| 接頭辞 | きっかけ | 編集者 |
|---|---|---|
| `EVT` | セルの編集（`recordDiffEdit`） | 編集した人（取れなければ `取得不可`） |
| `REC` | 取りこぼしの回収（`catchUpDiffTracking`） | `不明（取りこぼし回収）` |
| `ROW` | 行の追加・削除・ずれの突き合わせ（`diffResyncRows_`） | 行を追加・削除した人／`不明（行の追加・削除）`（編集トリガーから突き合わせたときも、編集した範囲の変更は `EVT`） |
| `CRD` | クレデンシャル履歴の登録・編集・削除 | 操作した人 |
| `SMP` | サンプルデータ（`サンプルデータ.gs`）。過去の日時で記録する | `サンプルデータ` |

## 処理の流れ

### 差分追跡

インストール型トリガーが3つあります（`setupDiffTracking()` が設置）。

1. **編集（`recordDiffEdit`）**：編集された範囲だけを比較基準と比べ、変わったセルごとに差分を記録します。
   順番は「最終更新日時 → 差分ログ → スナップショット → 比較基準の更新」です（スナップショットに最終更新日時が入るように、また記録が書けてから基準を進めるように）。
   その前に、行数の変化と行のずれ（下記）を確かめ、あれば先に行を突き合わせます。
2. **構成の変更（`pauseDiffOnStructureChange`）**：
   - 行数だけが変わったとき：比較基準の行と今の行を突き合わせ（`diffResyncRows_`）、
     消えた行を `行削除`、増えた行を `行追加`、同じ行で変わったセルはセルの変更として記録し、比較基準を取り直します。
   - 行の追加・削除の通知なのに行数が変わっていないとき（削除と追加がトリガーより先に両方起きた）：操作したシート（アクティブなシート）だけ行のずれを確かめ、ずれていれば同じように突き合わせます。
   - 列の追加・削除、シートの削除：そのシートの追跡を止めます（`DIFF_RULES` の列指定がずれるため）。
3. **取りこぼしの回収（`catchUpDiffTracking`、5分ごと）**：印の付いたシートだけを処理します。行数の変化・行のずれがあれば突き合わせ、
   無ければ、データのある最後の行までを比較基準と比べて記録します（「行の確かめ」の印だけなら、全セルは比べません）。

ロックが取れないとき（ほかの実行が書き込み中）は、エラーにせず印を付けて回収に任せます。
編集のときは、そのシートに「取りこぼし」の印を付けます。構成の変更のときは、行数・列数が変わったシートと操作したシートだけに「行の確かめ」の印を付けます（全シートを全セル比較にしない）。
記録の途中でエラーが起きたときは、そのシートの追跡を止めます（編集のときはトーストでも知らせます）。

#### 行の突き合わせと、行のずれ（v6）

- **突き合わせ（`diffResyncRows_`）**：比較基準と今の行を、行の中身で LCS により対応させます（`diffAlignRows_`。前後の一致を除く）。
  対応しなかった行は `diffPairRows_` で組にします。見分け列（`DIFF_ROW_OPTIONS.keyHeaders`：`得意先`・`案件名`）の値が同じ行は、離れていても同じ行とみなし（移動・並べ替え・ずれたあとの編集）、変わったセルだけを記録します。
  残りは、すき間ごとに同じ数なら位置で組にし、数が違えば `行削除`・`行追加` にします。移動しただけの行は何も記録しません。
- **ずれの検知（`diffRowsShifted_`）**：ある行の見分け列の値が、比較基準では別の行にあった値なら「ずれた」とみなします。
  比較基準のどこにも無い値（新しく入力した・書き換えた得意先）は、ふつうの変更として扱います。編集で見分け列そのものを変えた行は手がかりにしません。
  読むのは見分け列をまたぐ1つの範囲（シートと比較基準）を、データのある最後の行までだけです。
- **編集トリガーから突き合わせたとき**：編集した範囲の変更はふつうの編集（`EVT`・編集した人）として記録し、それ以外の未記録の変更は `ROW`・編集者 `不明（行の追加・削除）` で記録します（編集した人の変更にしない）。
- **調べるシート**：編集トリガーは編集したシート、変更トリガーは行数が変わったシートと操作したシート、取りこぼし回収は印の付いたシートだけです。追跡シートが11個あっても、1回の処理で全シートを読むことはありません。
  変更トリガーの通知にはシートの情報が無いため、操作したシートはアクティブなシートで判断します。取れなかったシートのずれは、そのシートの次の編集・取りこぼし回収で気づきます。
- **見分けられない場合**：`得意先`・`案件名` がどちらも同じ行が複数あると、並べ替えのあとに組を取り違えることがあります（同じ得意先の中での取り違えなので、ほかの得意先の履歴には混ざりません）。

### クレデンシャル・オファリング履歴

1. ボタン列をチェックすると `onCredentialLauncherEdit`（インストール型 onEdit。2つのボタン列で共通）が動き、
   見出し行を1回読んでどちらのボタンかを判断し、すぐにモーダルを開いてチェックを戻します。
2. モーダルは開いてから `getCredentialDialogData()` で履歴を読み込みます（ボタンを押してから開くまでを速くするため）。
3. 登録・編集・削除は、画面を先に更新し、サーバーへは1件ずつ順番に送ります。サーバー側では
   - ドキュメントロックを取り（`credWithLock_`）、
   - 行の得意先が開いたときと同じか（`credTarget_`）、
   - 編集・削除なら、開いたときの内容から他の人が変えていないか（`credExisting_`）
   を確かめてから書き込み、`変更履歴_差分` にも `CRD` で記録します。差分ログへの記録に失敗しても本体の保存は取り消さず、警告を返します。
4. 予定と実績：`実施日` が空なら「予定」、入っていれば「実績」です。どちらか一方の日付が必須です。
5. 紐づけ：オファリングは、同じ得意先のクレデンシャルに紐づけられます（1つのクレデンシャルに複数）。
   紐づくオファリングがあるクレデンシャルは種別を変えられません。クレデンシャルを削除すると、オファリングは紐づけなしで残ります。

### 変更履歴

`変更時点スナップショット` から「シート＋得意先」が一致する記録を新しい順に最大300件読み、
同じイベントIDの `変更履歴_差分` から、その行のセルの変更前・変更後を取り出します。
差分ログが見つからない記録は、1つ前のスナップショットとの違い（最終更新日時は除く）で補います。
記録は行の順ではなく `記録日時` の順に並べ替えてから使います（サンプルのように、過去の日時の記録があとから足されることがあるため）。サイドバーも同じです。

行番号は行の追加・削除や並べ替えで変わるため、行番号では探しません。得意先名を変える前の記録は表示されません。
同じイベントに複数の行の記録があるときは、セルの行番号で分けます（`chgRecordOfRow_`。サイドバーも同じ）。削除された行の記録（`N行（削除前の行番号）`）は、残っている行の履歴には出しません。

### 履歴サイドバー

- Apps Script にはサイドバーへ選択の変化を知らせる仕組みが無いため、サイドバーから「今選ばれている行」を問い合わせ続けます
  （操作中は0.25秒、しばらく操作がなければ1.2秒・4秒と間隔を空ける。前の問い合わせが返ってから次を送る）。
  同じ行なら得意先を読まずに返します。
- 履歴は全得意先ぶんを1回でまとめて読み込み（`getSidebarBundle()`）、行が変わるたびには読みません。1分ごとに読み直します。
  変更の記録は、シート・得意先ごとに新しい方から `HS_OPTIONS.eventsPerCustomer`（30回）まで読みます。それより古い記録がある行は
  `changesMore` で知らせ、一覧の最後に「それより前は「変更の詳細」で確認できます」と出します。
- 画面は「表示中の行」のカードと、「クレデンシャル」「変更履歴」の2つのタブです。
  - 得意先名の右の「アカウントプラン」は、`HS_OPTIONS.accountPlan` のシート（既定は `33シナリオ攻略先リスト`、E列が得意先、M列が URL）から
    同じ得意先（`credNormalize_` で照合。同じ得意先が複数あれば上の行）の URL を探し、新しいタブで開くリンクにします。
    セルに URL がそのまま無いときは `HYPERLINK` の数式とセルのリンクも見ます。`http(s)` 以外はリンクにせず、URL が無い得意先では押せない表示（灰色）にします。
  - クレデンシャル：オファリングは紐づくクレデンシャルの下に字下げして並べます。項目を押すと、その履歴を編集する状態でモーダルを開きます。
    予定（実施日が空）の項目は日付の前に「予定」、予定日を過ぎていれば「期限超過」を付けます。
  - 変更履歴：変更を項目（列）ごとに1件として、日ごとにまとめて新しい順に並べます。期間（過去7日・14日・30日・すべて・日付の指定）、
    7日ぶんの帯で選んだ日、項目（複数選択）で絞り込めます。「変更の詳細」は変更履歴のモーダルを開きます（日・項目で絞り込んでいるときは、表示中のいちばん新しい変更の位置で開く）。
- 開いたときの自動表示はインストール型の起動時トリガー（`autoOpenHistorySidebar`）です。単純トリガーの `onOpen` ではサイドバーを開けないためです。
- サイドバーから呼ぶ関数（`getSidebarSelection`・`getSidebarBundle`）は、開いた本人の権限で動きます。起動時トリガーは管理者の権限で動くのでサイドバーは出ますが、
  まだ承認していない人は呼び出しが失敗します。そのときは再試行の間隔を延ばし（10秒）、「権限の承認が必要です」と「承認する」ボタンを表示します。
  承認が済めば、開き直さなくても次の問い合わせから表示が始まります（ボタンを押してから5分間は3秒ごとに問い合わせる）。
- 「承認する」ボタンは、承認用のウェブアプリ（`doGet`。「ウェブアプリにアクセスしているユーザー」として実行）を新しいタブで開きます。
  サイドバーの中からは承認の画面を出せず、`ScriptApp.getAuthorizationInfo().getAuthorizationUrl()` もサイドバーを開く起動時トリガー（管理者の権限）の中では空になるためです。
  ウェブアプリは、まだ承認していない人には Google の承認画面を出し、承認が済むと `AuthorizeView` で「権限の承認が完了しました」と出します（一部の権限を外した人には、もう一度承認するリンクを出す）。
  URL は `HS_OPTIONS.authorizeUrl` に管理者が設定し、`openHistorySidebar()` がテンプレートの `authorizeUrl` としてサイドバーに渡します（`…/exec` の形でなければ渡さない）。
  未設定のときはボタンを出さず、メニューでの承認を案内します。
- 読み取りだけなのでロックは取りません。

### オポチュニティキャンバス

サイドバーの「キャンバス」（またはエディタから `openOpportunityCanvas()` を実行）で、その行の値をキャンバスの枠に並べて表示します（読み取りだけ）。

- どの列をどの枠に出すかは `OC_OPTIONS.sections` の見出し名で決めます。列の位置ではなく見出しで探すので、列を動かしても使えます（改行・空白、全角・半角の違いは無視）。
  見つからない見出しはモーダルの下に「見つからない列があります」と出します。
- 枠の内容と合う列だけを入れます。新FMT に当てはまる列が無い枠（利用の指標・予算・ビジネス上の課題）は出しません。枠の名前は日本語です。
- 出すのは追跡シートの行に入力されている値だけです（クレデンシャル・オファリングの履歴や体制は含めません）。値を自動で考えて埋めることはせず、空のセルは「未入力」と出します。
- 見出しの上に案件名・得意先・案件ステータス・最終更新日時、右上にアカウントプランへのリンク（行の「アカウントプラン（リンク）」、無ければ 33シナリオ攻略先リスト）。
- 「印刷・PDF」は、決まった幅（1400px）で並べてから A4 横1枚に収まるよう縮めて印刷します（印刷画面で PDF に保存できる）。
- 右上の「− 倍率 ＋」でキャンバスを拡大・縮小できます（50〜200%。倍率を押すと 100%）。「全体を表示」は、キャンバス全体がスクロールせずに見えるいちばん大きい倍率（100% まで）にし、モーダルの大きさが変わったら合わせ直します。
  倍率はキャンバス（`#canvas`）にだけ CSS の `zoom` でかけ、見出しと操作ボタンの大きさは変えません。文字が大きくなるぶん枠の中で折り返すので、横にはスクロールしません。倍率はブラウザ（`localStorage`）に覚え、印刷のときは 100% に戻します。
- 見出し・メニュー・ボタンの名前は日本語だけにします（「オポチュニティキャンバス」。英語の「Opportunity Canvas」は出さない）。

| 番号 | 枠 | 新FMT の列 |
|---|---|---|
| 1 | 課題 | クライアントが置かれている状況・課題・現在の解決策 |
| 1 | 解決策のアイデア | 案件のスコープ・サブインシナリオ |
| 2 | 顧客・ユーザー | サブインダストリー・先方部門・先方担当役職・先方担当氏名・本案件におけるターゲットユーザー |
| 3 | 現在の解決策 | スコープに対する競合他社 |
| 4 | 使われ方・導入効果 | 想定される価値創出のケース／期待される導入効果 |
| 5 | 導入戦略 | 提案を勝ち取るための戦略・差異化要素・活動状況 |
| 6 | ビジネス上の効果・指標（下の段） | 想定売上規模（百万）・期待値調整済 想定売上規模（百万）・受注月・売上開始月 |

### アカウントプランシート作成（`コード.gs`）

メニュー「アカウントプランシート作成」→ シート名を入力 → 対象件数（E列が入力済みで M列が空）を確認 → 実行、の順です。
1行ずつテンプレートをコピーして M列に URL を入れ、5分たったら中断します（もう一度実行すると、M列が空の行だけを続けて処理します）。

- 1行ごとにドキュメントロックを取り、ロックの中で「行の内容が読み込んだときと同じか」を確かめてからコピーします
  （処理中に行が挿入・削除されても、違う行に URL を入れないように）。ロックが取れなければ、コピーせずに止めます。
- 追跡シートに書き込んだときは取りこぼしの印を付けます。スクリプトの書き込みでは編集トリガーが動かないためで、
  次の回収で `REC`（編集者 `不明（取りこぼし回収）`）として記録されます。

### サービス管理（`ServiceManagement.gs`）

流れは「リクエスト（新FMT の Z列）→ サービス案（リクエストをもとに考え、名前でまとめる）→ タスク（サービス案の検討の進捗）」です。

- サービスは最初から決まっているものではなく、リクエストをもとに考えるものなので、サービスの一覧のシートは持ちません。
  `リクエスト` の `サービス案` の列に付けた名前がサービス案で、同じ名前を付けたリクエストが1つのサービス案にまとまります（多対1）。
- `リクエスト` シート：1行が1件のリクエスト。`サブインダストリー`・`得意先`・`案件名`・`リクエスト` の4列はすべて連動プルダウンで、候補は新FMT から自動で作ります。
  `判断`（プルダウン）・`サービス部門からのフィードバック`・`サービス案`（まとめる先の名前）・`担当者`（この3列は自由に入力・入力規則なし）は人が入れます
  （スクリプトは `リクエスト` より右の列に値を入れません）。
  前からあるシートに足す列は、`insertAfter` の見出しのすぐ右に差し込みます（`taskEnsureHeader_`。フィードバックは判断の右、担当者はサービス案の右）。
  差し込んだ列は左の列の入力規則を引き継ぐことがあるので、自由に入力する列の入力規則は `svcApplyRules_` で外します。
  使わなくなった列（`removedColumns`：`メモ`・`追加日`・前の版の `取り込み日`）は、`setupRequestSheet()` が確認してから削除します（`taskDeleteColumns_`）。
- シートを足した・名前を変えたあとの設定は `setupAfterSheetChange()`（`test.gs`）でまとめて行います。先に `diffCheckSheets_()` で全シートの見出しを読むだけで確かめ、
  足りなければ何も変えずに知らせます（途中で止まって、差分追跡だけ・ボタン列だけが設定された状態にしないため）。
  そのあと `setupDiffTracking()`・`setupCredentialLauncher()`・`setupChangeHistoryLauncher()`・`svcSetupRequestSheet_()` を順に呼びます（どれも何度実行してもよい）。
- シート名を変えた追跡シート：差分追跡の記録（`変更履歴_差分`・`変更時点スナップショット`）はシート名で残り、記録は書き換えないので、
  `DIFF_RULES` の `formerNames` に前の名前を書きます。読み手（`Changehistory.gs`・`HistorySidebar.gs`）は `diffSheetNameResolver_()` で前の名前を今の名前にそろえて見ます。
- 読むシート（`svcSourceSheets_`）：`DIFF_RULES` で `requests: true` を付けたシートです。新FMT の名前と見出しの行を `DIFF_RULES` の1か所に置くため、
  `SVC_OPTIONS` には読むシートを書きません（シート名が2か所にあると、片方だけ直す間違いが起きるため）。
- 候補：新FMT でリクエストが入っている案件（`svcSourceRecords_`。得意先・案件名・リクエストの組で1つ）のうち、
  ほかの行でまだ選んでいないものだけです。行ごとに、左の列で選んでいる値で絞り込みます。
  候補はスクリプトではなく、非表示の `__REQUEST_LISTS` シートの数式で作ります（`svcBuildLists_`・`svcListFormula_`）。
  `リクエスト` の n 行目の A〜D のプルダウンは、`__REQUEST_LISTS` の n 行目の欄を範囲で参照します（`requireValueInRange`）。
  選ぶたびに `onEdit` でプルダウンを付け直すと、処理が終わるまで（数秒）次の列を選べず使いものにならなかったためです。
  数式はシートが計算するので、左の列を選ぶとすぐに右の列の候補が変わります。
  全角・半角と空白だけが違う値は、列ごとに最初に出てきた書き方にそろえて `__REQUEST_LISTS` に書きます（`svcListRecords_`。数式では見分けられないため）。
  左の列から順に選ぶので、左に空の列がある列は「（先に〇〇を選んでください）」（`chooseLeftFirst`）だけの一覧にします（選んでも入らずに知らせる）。
  入力規則を外すのではなく案内の一覧にするのは、何を先に選べばよいかをプルダウンとヘルプで示し、手での入力も入力規則で止めるためです。
  新FMT でサブインダストリー〜案件名のどれかが空の案件は、左から選べないので候補に出さず、`setupRequestSheet()` で件数を知らせます。
  入力済みの行は、その行で選んでいる案件も候補に入れます。候補が無いときは「（すべて選択済み）」だけの一覧にします
  （新FMT にリクエストが1件も無いときは「（新FMT にリクエストがありません）」にして、すべて選んだときと区別する）。
  入力規則が無いと何でも入力できてしまい、「候補が無い＝すべて選んだ」と分からないためです（選んでも入らずに知らせる）。
  `__REQUEST_LISTS` の案件（A〜E 列）は、新FMT を編集するたびに書き直します。行ごとの候補の数式とプルダウンは、次のときだけ作り直します
  （`relayout`）：`setupRequestSheet()`・`removeUntouchedRequests()`、新FMT で候補が欄に入りきらなくなったとき、
  `リクエスト` の行数・読む列が変わったとき、編集した行のプルダウンがほかの行の欄を参照していたとき（行の追加・削除・並べ替えでずれる。`svcListsInPlace_`）。
  欄の幅は、候補の数に余白（`listMargin`）を足したものです。入りきらない候補は数式が `#REF!` になるので、作り直しで防ぎます。
  `setupRequestSheet()` の最後に、最初の行の候補に `#` で始まる値（数式のエラー）が無いかを確かめて知らせます（`svcCheckLists_`）。
- 選んだ行（`svcFixEditedRows_`。`onEdit` で行う）：編集した連動列から右で、左の列が空の値と候補に無い値を空にし（編集した列の値なら知らせる。左の列を消して右の列を空にしたときも知らせる）、
  左から選んだ値に合う案件がどれも同じ値になる次の列を埋めます（埋めるのは得意先・案件名だけで、左の列が空の列・人が消した列・`リクエスト` は埋めない）。
  入力した値を空にした行は埋めません（貼り付けで重なったときに、別の案件で勝手に埋めないため）。
  プルダウンは付け直さず、新FMT も読みません（読むのは見出し・`__REQUEST_LISTS`・連動列の3回）。候補は数式がすでに変えているので、
  この処理が終わるのを待たずに次の列を選べます。
  前の版で付けた保護（A〜D を手で変えると警告）は外します（今は A〜D をプルダウンで選ぶため）。
- 新FMT の変更（`svcHandleSourceEdit_` → `svcSync_`）：選んだ行だけを合わせます（行は足さない）。サブインダストリーは同じ案件の値にそろえ、
  1つのセルの書き換え（`e.oldValue` がある）で得意先・案件名・リクエストが変わったときは、古いキーの行をその場で直します（新しいキーの行がまだ無いときだけ）。
  リクエストの書き換えで、すでにサービス案・判断を付けていた行には「新FMT でリクエストが書き換えられました」の注を付けます。
  新FMT に無い行は消さずに注を付けます（新FMT に戻ったら外す。利用者が書いた注は変えない）。そのあと `__REQUEST_LISTS` の案件を書き直します。
- 単純トリガーの `onEdit`（このファイル。プロジェクトに1つだけ）が、新FMT とリクエスト シートの編集を振り分けます。
  新FMT の編集ごとに見出しの行を1回読み、読む4列にかかっていなければ戻ります（`リクエスト` シートが無ければ読まずに戻る）。
  単純トリガーは編集した本人として承認なしで動くので、まだ承認していない人の編集でも動きます。インストール型にしないのは、トリガーを増やさないためです。
  差分追跡（`recordDiffEdit`）も同じ編集でロックを取りますが、待ち時間が60秒あるので、重なっても記録は止まりません。
- 文字列は先頭に `'` を付けて書きます（`credText_`）。書き込みはドキュメントロックの中で行います。
- `判断`・`サービス部門からのフィードバック`・`サービス案`・`担当者` の編集では何もしません（`onEdit` はすぐ戻る）。判断を自動で入れることもしません。
- 前の版の見出し（`サービス`）は、見出しの用意（`taskEnsureHeader_` の `aliases`）で `サービス案` に書き換えます。
  前の版で全件を自動で取り込んだ行は「選んだ行」として残るので、`removeUntouchedRequests()` で手を付けていない行（判断が未判断か空で、フィードバック・サービス案・担当者が空）を
  確認してから削除できます（続いている行はまとめて `deleteRows`。データの行をすべて消すときは、先に空の行を1つ足す）。

### タスク管理（`TaskManagement.gs`）

シート `タスク管理` の1行が1件のタスクで、サービス案ごとの検討の進捗を管理します。
列は `サービス案`・`タスク`・`担当者`・`期限`・`状況`・`メモ` で、今は手で行を追加します（自動で行を作る処理は無い）。

- タスクはサービス案に対応付けます（案件には対応付けない。案件はサービス案にまとめたリクエストからたどれる）。
- `サービス案` の入力規則は、`リクエスト` の `サービス案` の列（`E2:E`）を範囲で参照し、範囲に無い値は入力できないようにします
  （`svcServiceRule_`。リクエストに付けた名前からだけ選ぶ。範囲で参照するので、リクエストに名前を付けるとすぐに選べ、作り直しは要らない）。
  名前を変えたときに参照先を書き換える処理はありません（リクエストの1つのセルの変更が「名前の変更」か「別のサービス案へのまとめ直し」か見分けられないため）。
  名前を変えるときは、スプレッドシートの「検索と置換」ですべてのシートを置き換える運用にします。
- タスク管理シートの編集では何もしません（`onEdit` はすぐ戻る）。
- `setupTaskSheet()` はシートが無ければ作り、見出しが空なら書きます。見出しがあるシートは書き換えず、足りない列だけを右端に足します（`taskEnsureHeader_`。リクエスト シートでも同じ）。
  全行（最後の行まで）に、サービス案・期限（日付）・状況（一覧）の入力規則を付けます。
- 前の版（案件の連動プルダウン `サブインダストリー`・`得意先`・`案件名` の列がある）のシートは、`ui.alert` で確認してからその列を削除し（`taskDeleteColumns_`）、
  `サービス案` の列を左端に動かします（`moveColumns`）。ほかの列の値は残ります。確認はロックを取る前に行います（答えるまでほかの処理を待たせないため）。

### 列の保護（`自動入力部分のシート保護.gs`）

`protectSpecificColumnsWithLock()` を手動で実行すると、名前が `案件_` で始まるシートの P・R・T・X・AA・AB 列を
実行した人だけが編集できるように保護します。同じ説明の保護が既にあれば作りません。

## 判断の理由

- **比較の基準は「最後に取り込んだ値」**：承認済みの値ではありません。取り込みの間にあった途中の状態は残らないため、完全な監査証跡ではありません。数式は計算結果ではなく式で比べます。
- **シートの文字列は数式にならない方法で書く**：利用者の入力が `=` で始まると、そのまま `setValue` すれば数式として動きます。差分ログはリッチテキスト、記録シートは先頭の `'` で防ぎます。
- **ロックが取れない編集をエラーにしない**：同時に何人も編集すると、編集トリガーが重なってロック待ちになります。止めるより印を付けて回収するほうが、追跡を続けられます。
- **行の追加・削除では止めない、列の変化では止める**：行の増減は突き合わせで追えますが、列が動くと `DIFF_RULES` の列指定そのものがずれるため、人が確認してから取り直します。
- **行のずれは見分け列で確かめる**：並べ替え・ドラッグでの移動、トリガーより先に削除と追加が続いた場合は、シートの大きさが変わらないので行数では気づけません。そのまま比べると別の行の値が「変更前」になり、取りこぼし回収ではずれた行がすべて「変わった」と記録されてしまうため、得意先・案件名の位置で確かめます。全列を比べないのは、毎回の編集で読む量を小さくするためです。
- **追跡シートが多くても、関係するシートだけを読む**：トリガーは3つのままで全シートをまかなうため、1回の処理では、編集したシート・行数が変わったシート・操作したシート・印の付いたシートだけを読みます。印は全シートぶんを `getProperties()` 1回で読みます。
- **編集者は `e.user` から取る**：インストール型トリガーはトリガーの所有者の権限で動くので、`Session.getEffectiveUser()` は所有者を返してしまいます。
- **トリガーの所有者は1人（管理者）**：同じトリガーを複数人が設置すると二重に記録されます。設置する関数は「1つだけ存在する」ことを保証します。
- **メニューは「権限を承認する（初回のみ）」だけ**：承認の画面は、本人がメニューなどから関数を実行したときにしか出せません（開いたときのトリガー・サイドバー・ボタンからは出せない）。
  そのため、利用者向けの入口として承認の項目だけをメニュー「履歴機能」に置きます。実行すると `ScriptApp.requireAllScopes()` で、承認の画面で一部の権限を外した人にも承認し直してもらい、サイドバーを開き直します。
  管理者の作業（ボタン列の設定・自動表示の設置・サンプル履歴など）や選んだ行のモーダルを開く処理は、エディタから関数を実行します。
- **ボタンはチェックボックス＋インストール型 onEdit 1つ**：どの行から押したかが分かるよう各行のチェックボックスをボタンにし、承認の要るモーダルを開くためにインストール型の onEdit を使います。ボタン列が増えてもトリガーは増やしません。
- **モーダルの大きさ**：`showModalDialog` は開くときの大きさしか指定できないため、開いたあとに `google.script.host.setWidth()` でブラウザ幅の95%に広げ、次回のためにその大きさを覚えます。

### 形と余白

- モーダルの見出し：`padding: 16px 24px 20px 32px`、下に `--line` の線。上に小見出し（12px / 600 / `--muted`）、その下に得意先名と件数のチップ。
- 一覧はタイムライン：`128px（日付）| 20px（点と線）| 残り（内容）`、列の間は 16px。
- ボタン：高さ 30〜36px、角丸 7〜8px、主ボタンは `--teal`。フォーカスは `box-shadow: 0 0 0 3px rgba(54, 161, 145, .25)`。
- 読み込み中は画面全体に回転表示と経過秒数を出し、失敗したら「もう一度読み込む」を出します（回転は JavaScript で動かすので、OS の「動きを減らす」設定でも止まりません）。
- モーダルの見出し（タイトル・得意先名・件数）は画面の中に表示し、`showModalDialog` のタイトルは空白にします。

### サイドバー（`HistorySidebarView`）

幅 300px のサイドバーは、モーダルと同じ色・フォントで、白いカードを並べる形にしています（デザイン元「履歴サイドバー v2」）。

- 背景 `#F0F4F9`（スプレッドシートが描くサイドバーの上の帯と同じ色。帯の色はスクリプトから変えられないので、こちらを合わせている）。
- 画面はすべて白いカード（セクション）でできています。カードは幅を取るためサイドバーの左右いっぱいに広げ（左右の余白なし）、
  枠線 `#E3E8E4`・角丸 12px でそろえ、カードどうしは 8px のすき間で区切ります。
- タブ・ボタン・プルダウンは背景の上に直接置かず、必ずどれかのカードの中に置きます（デザインをそろえるため）。
  - 表示中の行のカード：上の段に状態（● 表示中の行）とその右に「シートから取得」の時刻、右上に再読み込み（1行に収めるためアイコンだけ。名前は title・aria-label）、得意先（右に「アカウントプラン」のリンクボタン。枠線 `#CFE3DC`・文字 `--cred`・高さ 26px）・シートと行（右にオポチュニティキャンバスを開く「キャンバス」ボタン）、区切り線の下に「この行の最終編集」、その下にタブ（セグメント。背景 `#E9EDEA`、選んでいるタブは白＋影、件数のバッジ付き）
  - クレデンシャルのカード：上に「登録・編集」、その下に一覧
  - 変更履歴の絞り込みのカード：期間・7日の帯、その下に区切り線と「項目」「変更の詳細」
  - 一覧のカードは中身に合わせた高さで、入りきらないときはカードの中でスクロールします
- 変更前は赤（文字 `#8C4A44`・背景 `#FBEFEE`・取り消し線、ラベル `#B4534B`）、変更後・入力は緑（文字 `#174F44`・背景 `#E7F4F0`）、空欄は灰色（背景 `#F3F5F3`）。
- 一覧の種別は名称の前にバッジで出します：「クレデン」（文字 `#1F5E55`・地 `#EAF5F2`）、「オファリング」（文字 `#6B4FB8`・地 `#F2EEFB`）。高さ 18px・角丸 5px・同じ系統の薄い枠線。色は詳細画面（`CredentialDialog`）の種別と同じです。クレデンシャルとの紐づきの線は `#D6CCF1`。
- 日の帯は、記録のある日だけ数字を濃くして件数を出し、選んだ日は `--cred` の塗り。日曜は `#B4534B`、今日は「今日」と表示します。
- 色はファイル先頭の `:root` に変数としてまとめています。

### 書き方の決まり

- 画面に出す文字は `textContent` で入れます（HTML として解釈しない）。`innerHTML` 系は固定のアイコン（SVG）だけに使います。
- サーバーの関数は `google.script.run` から呼べるよう、末尾に `_` を付けません。
- `Loading.html`（アカウントプランシート作成）は別の機能の画面で、この決まりの前からある簡単な画面です。

## テスト

### ロジック（`npm test`）

`tests/lib/gas-mock.js` が Apps Script のモックです。リポジトリ直下の `*.gs` を Node.js の vm に1つのグローバルスコープとして読み込み、
`SpreadsheetApp`・`PropertiesService`・`LockService`・`ScriptApp`・`HtmlService` などをこのプロジェクトが使う範囲だけ再現します。

- `createGas()` でテスト1件ぶんの環境を作ります。`tests/lib/fixture.js` の `setupProject()` は、新FMT・新FMT2 を作って管理者のセットアップまで済ませます。
- 利用者の操作は `gas.edit(sheet, 'F3', '受注')`（編集イベントを返す）・`gas.change('INSERT_ROW')`・`gas.select(sheet, 'E4')` で再現します。
- スクリプトの書き込みは `gas.writes` に「ロックを持っていたか」と一緒に残るので、書き込みがロックの中かを確かめられます。
- `setValue` の文字列は手入力と同じく変換します（`'` で始まれば文字列のまま、`=` なら数式、日付・数字は日時・数値）。
- vm の中で作られた値は `plain()` で普通のオブジェクトにしてから `deepStrictEqual` で比べます。
- テストはシート名の設定に左右されません。モックが `DIFF_RULES` を `新FMT`（`requests: true`）・`新FMT2` に、リクエスト・タスク管理のシート名を `リクエスト`・`タスク管理` に置き換えます。
  本物の設定は `createGas({realSheetNames: true})` で読み、形と名前の重なりを `tests/project.test.js` で確かめます。
- 数式はふだん計算しません。`gas.evaluateFormulas = true` にすると、`tests/lib/formula.js` が `__REQUEST_LISTS` で使う関数（IF・IFERROR・TRANSPOSE・UNIQUE・FILTER・SUMPRODUCT・COUNTA）だけを
  スプレッドシートと同じ考え方で計算します（文字列の比較は大文字・小文字を区別しない、空のセルは "" とも 0 とも等しいなど）。本物のシートで数式が通るかは、`setupRequestSheet()` のエラーの確認（`svcCheckLists_`）で確かめます。
- 使う API がモックに無ければ、モックに足してください。

### チェック（`npm run check`）

`scripts/check-syntax.js` が、`.gs`・`.html` がフォルダの中に無いか・構文・`.gs` と `.html` の同名・トップレベルの名前の重複・`onOpen` の数・
HTML ファイル名・メニューや `google.script.run` から呼ぶ関数の有無を確かめます。

### 画面（`.html`）

Playwright（Chromium）で HTML を開き、`google.script.run` をモックに差し替えると表示を確かめられます。

1. HTML の `<?= 名前 ?>` を値に置き換えて、一時ファイルに書き出します。
2. `page.addInitScript()` で `window.google = {script: {run, host}}` を入れます。`run` は `withSuccessHandler`・`withFailureHandler` を受け取り、
   呼ばれた関数名に応じてテスト用のデータを返す Proxy にします。`host` は `setWidth`・`setHeight`・`close` を空の関数にします。
3. `page.goto('file://…')` で開きます（`page.setContent()` では `addInitScript` が効きません）。
4. `#loading` が非表示になるのを待ってからスクリーンショットを撮ります。

Google Fonts が読み込めない環境では代わりのフォントで表示されるので、文字の幅は実際と少し違います。
